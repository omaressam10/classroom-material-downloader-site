Classroom Material Downloader — reviewer guide

Prepared 6 November 2026 · Version 0.3.2 · Omar E. Shady

Requirements and installation

  • Windows 10/11, 64-bit, internet access and a Google account with access to a Google Classroom course.
  • No paid app account, credit card, app phone verification, NVIDIA GPU, Python installation or Ollama installation is needed for downloading.
  • Run Classroom-Material-Downloader-Setup-0.3.2.exe and choose an installation folder. Leave optional background startup off if you only want to test manually.
  • Open Classroom Material Downloader. A new installation starts without connected accounts or courses and with AI disabled. No developer tokens, student files or saved account credentials are included.
  • Google may require its own sign-in verification; the app does not control or bypass Google or school security policies. The installer is not currently code-signed. This is disclosed rather than represented as a signed release.

Test the Google integration

  1. Open Accounts → Connect Google. Sign in using your own authorized reviewer/test Google account. Review the seven read-only/identity permissions and approve if appropriate. The browser returns to the desktop app through a temporary loopback callback.
  2. Choose courses, select a course you can access, choose an empty local destination, and confirm. A teacher-created test course should contain a material post with a PDF, an assignment with a PDF attachment, and an announcement with text and a PDF attachment. For a student test, the reviewer account must be enrolled in that course. Course access is governed by Classroom, not a developer account allowlist.
  3. Click Sync now. Files from the selected course are downloaded into local category folders. The app reports any files denied by Google without bypassing those restrictions.
  4. Open Announcements, select the same course and read the cached announcement. Use Open announcement in Classroom to compare it with the source.
  5. Open Files, select the course, expand a folder and open a downloaded PDF. Compare the filename and content with its corresponding Classroom attachment. Do this for the material, assignment and announcement attachments to demonstrate all three post-reading scopes.
  6. Run Sync now a second time. Unchanged files should not be downloaded again. A changed/new attachment can be checked by posting it in the test course using a separate authorized teacher account and syncing again.
  7. Open Settings → Privacy and local data to see disclosures and the exact local profile path.
  8. Disconnect the account in Accounts. Its local token and account/course selections are removed; downloaded files and historical caches are intentionally preserved. Revoke Google access in Google Account connections if desired. Exit through the tray menu before deleting the local profile and test materials to erase local app data.

Optional local AI

AI is not required for scope verification or downloading. If testing it, install Ollama separately, download a local model compatible with the PC, then enable it in Settings. No GPU is required, although CPU inference can be slow. Cloud-backed or unverifiable models are blocked before course content is sent. AI failure/timeouts fall back to folder rules. The app performs inference only; it contains no model training or fine-tuning function.

Scope-to-feature mapping

ScopeFeature and least-privilege rationale
openidGoogle sign-in identity context; combined with email to identify the connection. No app password is collected.
userinfo.emailDisplays and distinguishes connected Google accounts and routes each course to the correct account. No profile-photo/name or class-roster scope is requested.
classroom.courses.readonlyLists accessible active courses so users choose what to synchronize. No course creation or modification.
classroom.courseworkmaterials.readonlyReads material posts and their attachment IDs. Course-list access alone cannot return these posts.
classroom.student-submissions.me.readonlyReads the current user's visible assignment/coursework posts and attachments through courses.courseWork.list. The consent description mentions grades, but the app does not call studentSubmissions/grade endpoints or request grade fields. It does not request the broader students scope or submit work. This exact scope is configured, requested and verified working against the current account. Google's method documentation also lists the coursework.me.readonly spelling; no additional scope has been introduced.
classroom.announcements.readonlyDisplays selected-course announcements and discovers their attached materials. No posting/commenting permission.
drive.readonlyReads metadata, downloads attachment bytes and exports supported Google-native documents by IDs obtained from selected course posts. The app does not enumerate unrelated Drive files or modify Drive. drive.metadata.readonly cannot download content. drive.file does not automatically grant access to existing teacher-owned attachments merely because Classroom returned an ID, and would require a different per-file selection workflow for new attachments, preventing unattended selected-course sync.

Scopes except openid use the prefix https://www.googleapis.com/auth/.

Hosting and account access

The website is static information on GitHub Pages. It is not the Google integration entry point and receives no OAuth tokens or course content from the app. The desktop app talks directly to Google over HTTPS. The OAuth callback binds to 127.0.0.1 on a temporary local port. Tokens are protected with Windows DPAPI for the signed-in Windows user. Other local files/caches are not separately encrypted by the app.

There is no developer-operated login or subscription account to supply. Reviewers can use their own authorized Google test account and Classroom test course. If the review team requires a developer-provided test course/account instead, request a secure reviewer-access arrangement; personal Google passwords are not part of this package.
